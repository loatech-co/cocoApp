# Traspaso — 7.4 contrato, lado API (rama `feat/openapi`, sobre `test/api-standards`)

**Hecho**

- `@nestjs/swagger@11.4.7` + plugin del CLI (`api/nest-cli.json`: DTOs `.dto.ts`/`.response.ts`, `classValidatorShim`, comentarios → `description`).
- Las 52 rutas v1 tal cual son hoy: envoltorio `{ data, meta }` (`meta` vacío, `{ total }` o `{ page, per_page, total }`), errores `{ error: { code, message, details } }`, bearer en las autenticadas, cabecera `x-coco-cliente` en login/refresh/logout, multipart en la subida de soportes y binario en la descarga.
- Respuestas como clases en `api/src/contract/v1/*.response.ts`; `shapes.spec.ts` falla en `tsc` si una se separa de la vista que devuelve su servicio (`Wire<T>`: bigint → number).
- `npm run openapi --workspace api`: `nest build` + app en modo preview (sin base ni secretos) → `api/openapi.json` (determinista). CI lo regenera, falla si difiere y lo sube como artefacto `openapi`.
- `/api/docs` solo fuera de producción (`setupApiDocs` en `main.ts`); comprobado en local contra la base de pruebas, CSP de helmet incluido.
- `test/openapi.e2e-spec.ts`: rutas de Express = rutas del documento (en los dos sentidos), las seguras dan 401 sin token, las públicas son exactamente las `@Public()`, y `/api/docs` sirve las mismas rutas.
- CONTRIBUTING: sección «API contract (OpenAPI)». `knip.jsonc`: el generador es entrada (fuera de la lista del paso, imprescindible).

**Decisiones**

- Los ids van como `number` (sin `format: int64`); los estados de error por ruta son una aproximación por módulo (grep de `DomainError`), no una auditoría.
- `POST /categories/{id}/unificar` devuelve `destino.parentId` en camelCase: documentado como es (`CategoryRecordResponse`); se corrige en v2.
- Exportados `CategoryPayload` y `RespuestaDeSesion` de sus controladores para la comprobación de formas.

**Plan v2 (siguiente paso del contrato, sin implementar)**

1. `src/contract/v2/` con clases nuevas: inglés + camelCase (mapa de 83 campos en `audit.md`), ids como cadena si se decide; v1 no se toca.
2. Controladores v2 propios (`@Controller({ path, version: '2' })` o prefijo `api/v2`), que llaman a los mismos servicios y mapean vista → v2; nada de lógica nueva.
3. Paginación D9: `{ data, meta: { page, perPage, total } }` en tablas y `nextCursor` solo donde se añade al final; los dos envoltorios una vez en `common/`.
4. Un documento por versión (`openapi.v1.json`, `openapi.v2.json`) con el mismo guardia e2e; Orval (fetch) en la web y luego iOS contra v2.
5. v1 con cabecera `Deprecation` y registro de cada uso; se retira tras siete días sin usos (7.10).
