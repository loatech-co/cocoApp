# Traspaso — 7.4 contrato v2, lado web (rama `feat/web-api-v2`, sobre `refactor/web-reuse-rules` #37)

**Hecho**

- Orval 8.40 (`client: 'fetch'`, sin hooks) genera `frontend/src/shared/api/generated/` desde `api/openapi.v2.json` (copia exacta de #36). **Versionado**: hbuilds construye sin devDependencies; el CI lo regenera (`npm run generate:api --workspace frontend`) y falla si difiere. Fuera de lint, knip y cobertura; `orval.config.ts` fuera del build.
- `apiRequest` (en `api-client.ts`) es el `mutator`: token, renovar, un reintento tras 401, sobre de error. Cada `api/` de feature llama a las funciones generadas; hooks a mano. Listas con `allPages` (`shared/api/pages.ts`). Campos en camelCase/inglés; textos sin cambios.
- Bordes traducidos una vez: sesión del puente v1 (`desdeElPuente`), `palabras_clave` de `@coco/lectura` (`shared/lib/arbol-buscable.ts`), nivel y granularidad del resumen. Origen: `VITE_API_ORIGIN` (antes `VITE_API_BASE_URL`; cada `.env` local se renombra).
- `packages/types` borrado. Lo que no está en el OpenAPI vive en `frontend/src/shared/lib/native-contract.ts` (puente, `USER_AGENT_APP`, contrato v1 del teléfono, mismos literales). Regla depcruise `web-ui-knows-no-contract` (probada con sonda).
- Verificación: typecheck, lint, prettier, knip, depcruise, 381 + 639 pruebas, cobertura, 193 e2e API (`coco_e2e_wv2_test`), build, Storybook, instalación limpia. Recorridos de #34: **26/26** contra la API de #36 (rama temporal con ambos, ya borrada).

**Decisiones**

- Toqué `api/src` en DOS specs, solo la ruta que leen (`soportes.contrato.spec.ts`, `interpretacion.contrato.spec.ts` → `native-contract.ts`); sin eso la suite de la API fallaba al borrar `packages/types`.
- `session.ts` escribe sus rutas `/api/v2/auth/*` a mano: usar las generadas creaba un ciclo con el `mutator`.
- `Cambios<T>`: el documento v2 no marca `nullable` los opcionales que la API acepta en `null` (PATCH de movimiento y categoría); se ensancha el tipo en un sitio.

**Pendiente**

- **#34 al integrarse detrás**: `e2e/support/fixtures.ts` `entrar` → `/api/v2/auth/login` (la cookie v1 no llega a la v2) y `e2e:build` sin `VITE_API_BASE_URL=/api/v1`. Con eso pasan los 26.
- **iOS** (no toqué `ios/`): `ContratosTests` lee `packages/types/src/index.ts` y ahora hace `XCTSkip`; debe leer `frontend/src/shared/lib/native-contract.ts` (mismos literales). Comentarios en `Contratos.swift`, `Marca.swift`, `Protocolos.swift` y `ios/README.md`. El puente no cambió; cambiará con iOS en v2 (y con él `desdeElPuente`).
- **Runbook** (`docs/runbook-adr`): tras desplegar la web en v2 cada persona entra una vez (cookie en `Path=/api/v2/auth`); el 401 del primer refresh lleva a «Entrar» sin error (prueba en `session.embebida.dom.test.ts`). **ADR 0013** dice «generated during build»: corregir a «versionado + chequeo en CI».
- API: marcar `nullable` en el documento v2 los campos que se limpian con `null`; `AuditEntry.action` y `PendingPayment.periodicity` salen como `string`.

**Borrado**: `packages/types`, la rama temporal y su base `coco_e2e_wv2pw_test`. Queda `coco_e2e_wv2_test` y `api/.env.test` (ignorado).
